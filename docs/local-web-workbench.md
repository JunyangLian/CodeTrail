# CodeTrail · 代码执行工作台

CodeTrail 表示“代码执行轨迹”，用于查看从任务输入、工具执行到结果验证的完整过程。项目基于 [Pico](https://gitee.com/htxoffical/pico) 二次开发，沿用底层包名、配置和数据目录；网页与终端展示名统一使用 CodeTrail。

启动命令：

```powershell
# 在 CodeTrail 项目根目录执行
python -X utf8 -m pico.web --cwd examples/interview-demo --model-timeout 180 --open
```

Windows 可双击项目根目录的 `start-web.cmd`。默认网址是 `http://127.0.0.1:8765`。
服务只绑定本机；不需要账号、前端构建或新的运行依赖。已有服务时直接访问网址。
`--model-timeout` 可设置单次模型请求的socket等待时间（1–300秒），模块和双击脚本默认180秒。OpenAI兼容后端最多3次传输尝试，重试前检查2倍配置超时的剩余预算；这不是严格的任务墙钟截止时间。修改后重启服务；工具命令有独立超时限制。失败传输用量未知，重试可能额外计费。

## 一次完整操作

1. 左侧新建会话，或选一个已有会话继续。模型使用本地 `.env` 中的配置；修改配置后重启服务。
2. 输入任务，或点击“读懂代码”“检查与修复”“验证结果”填入示例。
3. 选择“逐步确认”，点击开始。右侧会显示模型请求、工具调用、结果和恢复点。
4. 遇到写文件、执行命令时，中间出现审批卡片；核对工具名和参数，再允许或拒绝。
5. 结束后查看“代码差异”和“验证结果”。后者展示真实命令输出和返回状态，不是模型自评。
6. 点击“运行记录”查看落盘工件；左侧会话可以在重启服务后继续。

只读模式会拒绝文件写入和 shell；自动模式放行现有工具执行器允许的动作。
“已结束”表示模型已返回最终回答，不能单独证明功能正确，仍应查看命令输出和独立测试。

## 订单修复与结果判定

默认演示目录现在包含订单计价案例：商品数量、百分比折扣和折后运费三个缺陷，另保留原有加法案例。共 15 个测试；重置后预期 5 个失败、10 个通过。新建会话点击“检查与修复”即可填入完整任务，默认预算为 12 次工具调用。重复演示前，在演示目录执行 `python demo.py reset`，当前实现会先备份，测试与历史不变。详见 [案例说明](../examples/interview-demo/README.md)。

执行现场新增结果摘要，依据工具事件而非模型自评：

- 分别显示“模型已结束 · 未验证”“验证未通过”“验证命令通过”。
- 指定命令为 `python -m unittest discover -v`，只有命令匹配、真实退出码为 0 且工具正常结束才计为通过。拼接了其他 shell 指令的命令不会被算作同一次验证。
- 最近一次验证后文件又被修改，显示“需要重新验证”；审批被拒绝时显示“验证被阻止”。
- 鉴权、限流或额度、网络、模型超时、服务异常、回复格式和步数耗尽显示不同原因与处理建议。工具拒绝、命令超时和非零退出码保留在过程里；出现过失败但后来修复成功，也保留失败次数。
- 结果随运行记录保存，重新打开历史仍使用当时的验证命令。旧记录没有指定验证命令时保持“未验证”，可展开旧命令查看结果。

其他工作目录可显式指定验证命令，例如：

```powershell
python -m pico.web --cwd path/to/project --verify-command "python -m pytest -q"
```

这个参数定义结果判定依据及完成门槛，不会自动执行命令。模型必须调用正常工具并获得审批；最近一次修改后没有匹配命令的真实退出码0时，Harness要求继续修复。预算耗尽或验证被阻止时记录未完成。只读解释任务不强制运行shell。“验证命令通过”只表示该命令退出码为0，测试覆盖范围、测试是否被修改以及修复是否符合需求，仍需结合代码差异检查。

## 实现范围

- `pico/web.py`：Python 标准库 HTTP 服务、单任务后台线程、审批等待和运行记录适配。
- `pico/web_assets/`：HTML/CSS/JS，按一秒间隔读取任务进度。
- 沿用现有 Pico 主循环、模型协议、工具治理、会话和 checkpoint。
- 使用目录文本快照生成 diff，不要求演示目录有 Git。跳过 `.env`、内部状态、二进制、符号链接和大文件；最多取 400 个文本文件、2 MB，展示最多 20 个差异文件。它不是完整仓库变更审计。
- 原有 CLI 记录可查看过程和回答；只有经网页执行的新任务保存了网页差异快照。
- 页面刷新可以重新接上当前任务；服务重启后通过历史运行和会话继续。内存任务 ID 本身不跨服务重启。
- 审批绑定具体任务和审批 ID，不能重复使用。最多等待十分钟，超时拒绝。
- 网页不把 API Key 发送到浏览器；接口限制本机 Host，写请求校验随机令牌和 Origin。

这是本地单用户工具。没有多用户权限、任务并发队列、强制取消或操作系统级 shell 沙箱。
直接运行在可信示例上即可，不需要为面试再扩展这些功能。
