# CodeTrail 面试讲解：完整基础与具体工程问题

## 一分钟开场

> 我做的是一个本地代码Agent Harness，关注同一个仓库跨会话、持续变化时的执行可靠性。模型之外，我负责工具协议、上下文、记忆、审批、修改、验证和恢复。项目规模刻意较小，但有真实代码修复、独立验收和失败保留。最近把这些能力连成了一个小型工作台：源码变化会使相关知识和计划失效，压缩后能查回原始工具证据，中断后的未知副作用需要核对再继续。

补充边界：新增完整工作台已做机制和脚本化集成验证；当前硅基流动账户HTTP402，新Embedding和长任务机制的真实模型收益尚未验证。历史修复成绩对应历史配置，不能转移到新版。

## 为什么开发，而不直接使用DeepSeek Harness

DSH是通用插件化平台，适合直接使用和扩展。我的项目选择一个较窄的问题：代码版本变化、记忆复用与执行中断之间的冲突。我希望能解释某条知识的来源、是否仍有效、进入了哪一步、如何支持修改和验证，并用受控实验检查机制效果。

这体现问题选择、实现和验证的深度，不声称向量检索、事件日志或持久记忆是原创，也不推断竞品没有这些能力。

## 主要技术追问

**“向量转换具体做了什么？”**

源码按Python函数/方法与文本窗口分块，附路径、符号、行范围和源哈希。精确符号、BM25与真实Embedding候选用RRF融合。向量按模型/端点/分块版本和内容哈希缓存，校验维度、有限值和非零范数；模型失败明确降级。当前实现为小规模精确余弦检索，没有引入分布式向量库。Mock向量只测试协议与缓存，不证明语义质量。

**“为什么不全用向量？”**

代码符号和错误码需要精确匹配，业务描述又可能需要语义匹配。先用固定查询与证据金标比较检索，再检查预算后实际注入与最终修复。检索命中不等于模型使用正确，也不等于任务成功。

**“长期记忆和上下文摘要有什么不同？”**

工作状态服务当前任务；任务经历记录历史；仓库事实和流程可以跨会话复用。摘要是上下文压缩手段，记忆是带作用域和生命周期的知识。长期不代表永远正确。新prose保持候选，需要明确确认；自动沉淀仅限机械源码结构与实际验证产生的执行历史。

**“遇到知识冲突怎么处理？”**

同fact key版本通过事务替换，旧记录superseded；来源变化、TTL到期和撤销分别失效。不同key的自然语言矛盾尚无完整语义消解。文件哈希是保守依赖判断，AST关系也不是完整动态调用图。

**“上下文压缩丢失细节怎么办？”**

保留完整调用配对和关键约束，旧工具结果压缩为来源、预览和证据ID。原始脱敏输出放在会话隔离的证据库，支持查找与分页查回；旧内容作为历史材料，不自动变成当前事实。预算计量仍是明确标识的JSON字节估计，与服务商真实usage分开。

**“怎么防止没修好就说完成？”**

指定验证命令后，最后修改后的真实退出码与工作区快照共同决定完成门禁。verification计划步骤要求相应证据。外部验证器独立重测最终文件，Agent自述不能代替验收。通过仍受测试覆盖范围限制。

**“恢复是不是重跑一遍？”**

风险调用先记录意图，审批后核对快照，再记录执行状态和真实结果。进程在效果产生后退出，保留executing/uncertain并阻止自动重放。操作者核对后结束旧意图，再在新运行中重新审批。任意Shell外部副作用无法保证exactly-once；网页继续任务也不等于精确恢复服务商隐藏思考。

**“多工具调用如何安全？”**

完整配置最多8个原生调用，校验整批协议后串行调度；每项单独计步、检查权限、记录真实ID和结果。写入逐项审批，预算不够的调用明确未执行，最后一步保留验证。尚未并行写入。

**“有Skills、MCP、多Agent吗？”**

有最小实现：Skill索引按需加载正文；MCP用真实stdio子进程完成握手、发现与调用，自带一个文档搜索服务器；有界只读delegate限制深度和步数。扩展不提升权限，readOnlyHint不能作为信任依据。没有插件市场、任意远程服务管理或大规模Agent团队。

**“安全隔离覆盖多大？”**

Windows AppContainer只执行过滤副本和固定标准库测试命令，无网络能力，配合Job资源限制。host模式没有OS隔离。模型接口在宿主侧访问凭据，生成代码的测试环境不携带Key。新索引排除内部目录、历史评测资产和敏感文件。完整语义注入防护、内核攻击和任意依赖环境并未证明。

## 五分钟现场演示

1. 启动全新离线工作区，说明脚本化决策与真实工具执行的区别。
2. 展示计划、源码定位、首次失败测试；逐项审批修复和重新测试。
3. 展示实际差异、8条测试、原始证据ID和候选记忆，手工确认并刷新页面。
4. 使用专项报告说明源码变化后的失效与真实进程退出；指出阻止重复执行、人工核对和新审批的边界。
5. 展示软件回归和原始失败记录。现场有余额时另开真实模型运行，不能切换模式冒充。

## 简历可用的贡献表述

- 开发本地代码Agent工作台，统一原生工具调用、任务计划、代码编辑、执行审批、结果验证及审计流程，支持有界工具批次、流式反馈和中断任务继续。
- 实现带源码证据和版本的长期记忆管理，区分候选与确认知识，支持来源失效、TTL、撤销及跨会话召回；结合BM25、符号匹配和可配置Embedding构建小规模混合检索。
- 构建修改与验证的证据链，支持哈希预检、冲突安全撤销、原始输出查回和风险操作意图日志；通过真实故障注入检查未知副作用与重复执行防护。

测试数量与专项检查数量以本轮最终报告为准；它们是软件和集成验证，不能代替真实模型成功率、Recall提升或成本下降。未经新实验，不添加这类提升数字。
