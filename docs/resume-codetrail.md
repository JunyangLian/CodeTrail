# CodeTrail：本地代码 Agent Harness 与可视化评测工作台

更新日期：2026-10-26。

**核心技术：** Python、Native Tool Calling、Context Engineering、轻量记忆检索、Prompt Cache、Windows AppContainer、Agent Evaluation。

**项目描述：** 面向代码仓库长链路任务开发本地代码 Agent Harness，覆盖模型接入、工具调用、上下文管理、结构化记忆、运行审计与评测闭环，重点解决多轮任务中的上下文膨胀、重复读取、工具误调用和结果不可复现问题，并提供本地可视化工作台。

**核心职责与贡献：**

1. **Agent 执行架构：** 统一模型接入、7 类工具、会话状态与运行工件，完善原生 Tool Calling、reasoning 字段与 tool_call_id 传递，阻断混合协议误执行；为 Windows 状态持久化引入原子替换、最多 5 次有限重试及恢复审计。
2. **上下文与记忆治理：** 完善分层上下文预算、长文件分页读取及任务/文件/会话记忆管理，结合词法召回与内容哈希失效校验；审计 904 次工具执行，按冻结口径重复读取为 0/355，并核对工具结果向下一轮上下文的传递。
3. **工具安全与隔离：** 构建参数校验、路径限制、敏感信息脱敏与交互审批，引入 Windows AppContainer 私有副本及 Job 资源限制，限定单进程、256 MiB 内存，隔离不可用时拒绝执行；相同 14 项固定安全守卫全部通过。
4. **七维评测与审计：** 冻结 30 道代码修复任务，其中 18 道来自真实上游故障，建立覆盖正确性、上下文、忠实性、工具过程、稳定性、成本与安全的评测体系；90 次有效运行中 89 次通过独立外部验收，成功率 98.89%，归档完整轨迹、补丁、测试与 SHA256。
5. **可视化与端到端验证：** 开发本地网页展示工具审批、执行轨迹、代码差异、测试输出与历史回放，修复断连后轮询停止问题；通过真实 Tabbit 浏览器完成 3 类修复任务，每题独立验收 8/8 通过，全量自动化测试 309/309 通过。

## 面试时的指标口径

- 简历的 98.89% 是排除平台余额中断后的条件成功率：89/(144−54)=89/90。仅排除明确归因为 HTTP402 余额不足的 54 次，保留那次真实修复失败；不是全部尝试的无条件成功率，也不表示相对旧模型的因果提升。
- 30 是不同题目数，144 是实际修复执行次数。首批 90 次通过 36 次，54 次因余额不足中断；更换凭据后对中断槽位另行追加 54 次，通过 53 次。原始 144 条及总体 89/144 在完整报告中保持不变，不能把追加 53/54 当成整体成绩。
- 原 20 题是已知回归任务，新 10 题仅保证此前未用于本项目 Agent 调优；不能保证公开故障未进入模型预训练。网页三题是已知任务的集成验收，不加入 Benchmark 成功率。
- 0/355 是冻结定义下的重复读取口径，不代表必要文件召回率或记忆能力提升。Recall@5 历史主结果仍为 53.21%；无余额中断切片 81.55% 仅用于诊断，不能替代主成绩。
- 14/14 是固定安全守卫的新后端回归；历史 host 模式的 13/14 不变。AppContainer 共享 Windows 内核，不等于 VM 或所有逃逸路径均已覆盖。
- 309 是软件自动化测试数，不是独立 Agent 任务数。真实费用、长期记忆真实任务收益及广义语义忠实性没有可靠观测时不写量化提升。
- 原有 18.01% 上下文压缩、记忆正确率 66.7%→100% 等数字尚缺逐项对应原始快照，本版本不作为当前个人实测结果引用。
