# CodeTrail 订单计价修复演示

目标：根据真实测试失败，定位多个函数之间的业务问题，只修复实现，再运行同一组测试证明结果。

## 业务规则

- 商品金额是单价乘以数量之和；单价非负，数量必须是正整数（布尔值不算整数）。
- `discount_percent=10` 表示减免 10%，支付原金额的 90%；允许 0–100，超出范围报错。
- 金额使用 Decimal，按四舍五入 ROUND_HALF_UP 保留两位小数。
- 以折后商品金额判断运费：满 100 元免运费，否则运费 8 元；空订单为 0 元，无运费。
- `order_pricing.py` 是待修复实现，`test_order_pricing.py` 是 12 个业务验收测试。
- `calculator.py` 和其 3 个测试保留早期演示结果，不需要修改。总计 15 个测试。

## 重复演示

在本目录执行（从项目根目录可先 `cd examples/interview-demo`）：

```powershell
python demo.py reset
python -m unittest discover -v
```

重置只恢复订单实现中的三个故意缺陷，不改测试、旧案例或会话。若当前实现不同，会先备份到 `.pico/demo-backups/`。重置后测试失败是演示起点，修复成功后应为 15/15 通过。不要让 Agent 修改测试以隐藏问题。

网页中新建会话，点击“检查与修复”，查看提示词后开始；模式选择“逐步确认”，最多工具步数建议 12。提示词给出计价规则，要求先运行测试，再读取实现定位问题，只修改 `order_pricing.py`，最后重测。模型可以继续读取测试核对规则。写入和执行命令分别审批。

也可直接输入：

> 先运行 python -m unittest discover -v，再读取 README.md、order_pricing.py 和 test_order_pricing.py。只修复 order_pricing.py，修复商品数量、折扣和运费问题；不修改、跳过测试或运行重置。最后重新运行同一测试命令，说明实际结果和退出码。

结束后再独立运行同一测试命令，检查只有实现文件发生变化。网页把“模型已结束”和“验证命令通过”分开；最近一次验证后再改文件会提示重测。

`.pico/` 保存会话、运行过程、恢复点、网页差异和备份，可在“运行记录”复盘。重启服务后仍可查看历史结果。
