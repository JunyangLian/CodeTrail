## 独立审查发现与修复

| 缺陷 | 根因 | 修复与复验 |
|---|---|---|
| QA-01 保护路径递归读取绕过 | 只检查直接path，搜索/索引/符号未逐来源过滤 | 统一读取谓词，在读取和Embedding前过滤；记忆、证据、文档及沙箱副本一致应用；新策略不允许继续发送旧上下文 |
| QA-02 文档MCP硬链接绕过 | 子服务器自行读取，未继承文件边界 | 宿主传递允许文档清单，子服务器拒绝硬链接；原始合成canary不再出现 |
| QA-03 中断任务不可发现 | 只列完成report，active只存在内存 | 启动扫描任务快照，config与历史提供恢复入口，自动显示中断现场，旧审批作废 |
| QA-04 验证期间源码变化仍通过 | 只绑定测试后快照 | 工作区变化时标stale；完成门禁、verification计划和网页显示一致拒绝该通过声明 |
| QA-05 CRLF源SHA错误 | 通用换行归一后hash | 索引读取原始字节；返回SHA可直接用于编辑预检 |
| QA-06 关闭记忆仍注入 | 原生链路绕过feature flags | 原生与普通请求遵守开关；关闭候选、自动经历及旧记忆提升，保留必需执行状态 |
| QA-07 候选来源hash绕过授权 | memory_propose未检查evidence_paths | 计算哈希前逐路径授权；保护/硬链接来源不能通过候选入库读取 |

此外主流程修复了策略路径别名、审批后策略变化、证据ID未绑定参数/快照，以及完成视图尚未落盘就通知结束等问题。对应新增回归与独立探针均保留，不将其反推为历史模型实验的失败原因。

独立报告分别位于证据包的 `independent-qa/`（原始发现）、`independent-qa-after/`（首轮复验及QA-07）、`independent-qa-final/`（最终结论）。子代理未修改产品或tests，未调用外部API，探针前后产品源码SHA一致。

## 连续场景与真实中断

`scenario-release/` 在首次运行前冻结运行配置、全部pico源码及演示资产SHA。

实际链路：建立计划 → 定位源码 → 首次测试失败 → 修复实现 → 同一测试通过 → 候选确认 → 跨会话召回 → 源码接口变化 → 相关记忆与计划失效 → 新签名重新索引 → 子进程在文件效果产生后 `os._exit(77)` → 新操作被未决意图阻止 → 显式核对且不重放 → 独立复验8条测试通过。

该场景的决策由明确标记的脚本提供，证明工程机制联通，不证明模型会自主做出相同决策。4个直接安全守卫也只属于本场景的机制检查，不是新的大规模攻击评测。

## Tabbit真实网页证据

使用官方稳定启动器操控Tabbit，真实填写任务、点击逐项审批、观察测试与修改、确认记忆并刷新验证持久化。没有用直接调用后端代替点击。

第一次修复在 `web-demo-final/`；后续取消及继续产生两条stopped记录。最终恢复流程在 `web-qa-v3/`：

1. 在测试等待审批时停止服务，保存真实等待中的任务与操作意图。
2. 同目录重启服务，网页自动找回任务，旧“允许执行”按钮隐藏，恢复入口可见。
3. 独立核对当前文件快照与旧before_hash相等、实现尚未改变。
4. 在网页填写核对理由并结束旧意图，创建新运行和新审批。
5. 经新审批执行失败测试、修改、重测及MCP，最终通过并确认工作流候选。

`browser/run-audit.json`和CSV保留5条控制器运行；中断运行没有完成report的事实也保留。`browser/*independent-verification.json`记录最终两工作区的独立验收。新旧操作、审批、源差异、验收文件SHA和浏览器receipt可交叉核对。

截图成功2次并已实际查看；最终重启场景的2次截图请求超时，错误回执保留。超时后先只读检查，确认记忆active与实际验证通过，再尝试一次只读截图；没有重复点击确认或伪造图像。成功截图对应前一网页修复场景，不冒充最终重启时刻截图。浏览器正常启动后自动刷新了旧CLI注册，没有手工修改ACL或切换浏览器。

## 失败、开发迭代与历史保留

- `scenario-v1/`：14项前置检查通过后，故障注入子进程错误推断嵌套Git根，30秒超时；产生的唯一演示文件已核对、归档并移除，旧意图记录为显式结束且不重放。`misroot-reconciliation.json`保留证据。后续固定演示与完整配置的工作区根绑定。
- `scenario-v2/`、`scenario-v3/`、`scenario-final/`是开发中的不同版本，未替换原失败。最终发布源码的专项结果单列`scenario-release/`。
- 中间全量368条通过，随后独立审查发现额外缺口并修复；两次主动中断的全测保留日志和原因，最终380条在最后冻结源码上重新全部执行。不能把中间进度称为最终通过。
- 历史三个公开证据包SHA与原值一致；题目、验收测试与原结果未改变。检查记录在`historical-evidence-check.json`。
- 用户决定先完成离线功能验证后，没有继续外部模型或Embedding调用；早期代理TLS失败和直连HTTP402单独保留，未知usage保持未知。

## 复现命令

```powershell
python -X utf8 scripts/run_workbench_demo.py --offline --open
python -X utf8 scripts/check_workbench_scenario.py --output artifacts/your-new-workbench-check
python -m pytest -q --junitxml=artifacts/your-new-full-tests.xml
```

输出目录必须全新。独立Codex探针在新目录新建工作区运行；复测前复制脚本到同层的新目录，不能覆盖归档结果。SQLite所有者绑定、硬链接与进程状态需要在新场景重建，不承诺把归档工作区移到其他路径就能原样续跑。

## 证据包与结论边界

[证据包](evidence.zip)、[SHA256](evidence.sha256)和[结构化总表](summary.json)包含最终JUnit、源码/测试快照、源码清单、协议、SQLite一致性快照、场景、独立QA、浏览器回执与独立验收；逐文件SHA在包内manifest中。发布前扫描真实环境凭据，未将Key写入仓库。

可以据此说明主要功能已实现，已知7项反例已修复，选定场景可审计且能够恢复。尚不能说明真实Embedding提高Recall、记忆降低真实模型成本、新版提高代码修复成功率，或达到任意仓库/插件/外部副作用的生产级可靠性；这些需要下一轮受控模型实验。

公开证据包仅保留技术材料；个人准备文档及其入口已移出，原始包在本地保留。运行记录、产品源码与测试快照未改动，分发调整见包内 `publication-redaction.json`。
