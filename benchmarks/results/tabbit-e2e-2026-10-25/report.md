# CodeTrail 真实 Tabbit 网页端到端测试

日期：2026-10-25。结论：三个不同类型的冻结修复任务均通过网页完成审批、修复和重测，并通过独立验收；发现并修复一个状态轮询断连后永久停止的问题。本轮仅是集成测试，不计入历史 Benchmark 成功率。

## 环境与方法

- 使用用户已打开的 **Tabbit**，由官方稳定入口 `%LOCALAPPDATA%\Tabbit\LocalAgent\bin\tabbit-cli.exe` 操作。任务名 `CodeTrail E2E`，实例 `A002AC12F14892EA`。没有切换浏览器。
- 保留用户原有 `http://127.0.0.1:8765/` 标签；为三题建立三个全新工作区、独立 Web 服务与会话，分别位于 8766、8767、8768。最终保留结果页。
- 模型复用硅基流动配置：`https://api.siliconflow.cn/v1`、`deepseek-ai/DeepSeek-V4.1-Flash`、原生 Chat Completions Tool Calling。每次响应的模型标识在轨迹中保留。Key 从进程环境读取，未写入仓库或本报告。
- 请求 temperature=0.2、top_p=0.95；Thinking 及输出各请求 4096 Token；API 超时 180 秒，工具预算 20，三题并行提交。采样实际生效情况与不可变权重版本不由客户端控制。
- 明确使用 `shell_backend=appcontainer`；审批模式 `ask`。只批准冻结允许文件的补丁和精确命令 `python -B -m unittest discover -v`，没有扩大权限或修改金标。
- 首次提交前保存 `protocol.json`，包含题目、初始文件 SHA256、选择时间及源码基线 `7619605fb3736fc6a022c6ec41afa51501ab6eef`。冻结任务资产 SHA256：`dc7399a51e4f62e6ad1a1f669779487326be5f48f5ea7cdd898d1664f61a182c`。
- 提交、审批、拒绝、标签切换与历史回放均调用真实 Playwright 页面交互。独立验证在浏览器操作结束后，另建目录重新安装冻结测试，仅覆盖允许的实现文件，使用隔离 Python 外部验证器。

每题恰好一次真实修复会话，**功能与流程通过均为 3/3**。这三题是已知冻结任务，不能据此推断未见任务泛化能力。三题都保留首轮退出码 1、源码读取、获批补丁、最终退出码 0 和最终回答。测试与其他受保护文件哈希全部不变。

- 分页：修正页码从 1 开始、总页数向上取整和下一页边界。
- 用户查找：仓储增加既有 ID 规范化；服务层修正跨文件参数顺序。
- 行分隔：定位 `text_core.py`，修复 Unicode 分隔符正则转义。

每题均发生一次多工具调用包拒绝，模型随后改为单工具调用恢复；没有删除这些协议错误。没有发生补丁匹配失败，故本轮不宣称验证了真实模型的“补丁失败后纠错”能力。首轮测试失败后的定位与修复已验证。总计 20 个工具步骤，输入 104596、输出 3431 Token；费用未取得可靠账单，不估算为实付成本。

**已修复问题 E2E-01：状态轮询没有错误恢复。** 在 Tabbit 通过原生网络拦截仅中断一次实际状态 GET 请求，未伪造响应内容。旧版页面停在准备中，9 秒内未继续读取状态，后台已经等待审批。证据：`browser/repro-poll-interruption.receipt.json`。

修复 `pico/web_assets/app.js`：连续失败最多发起四次退避重试，间隔 1/2/4/8 秒；第五次失败后提示刷新，不继续无限请求。成功读取会重置失败计数并恢复 AppContainer 连接标识。旧任务响应不会更新新会话；历史列表刷新失败不再把已结束任务误标为连接中断。保持任务忙碌状态，避免网络不确定时重复提交。

Tabbit 重载新代码后再次中断一次 GET，页面显示正在重试，然后恢复同一审批内容，真实点击批准后完成测试。证据：`browser/verify-poll-recovery.receipt.json`。另外增加五个 JavaScript 行为测试，通过一个 pytest 入口执行，覆盖瞬断恢复、有限重试、计数重置、过期响应和历史刷新失败。

连接恢复与拒绝审批是 **两次额外交互探针**，使用分页题已经修好的工作区，不属于三次修复会话，也不新增独立任务或 Benchmark 结果。拒绝后状态为“已停止”，不是“已结束”，符合未通过验证不得完成的原有规则。

## 隔离与安全证据

三题共六次测试命令均记录 AppContainer 执行；六份审计均确认内核令牌 `kernel_token_is_appcontainer=true`、无网络能力、无宿主回退、无宿主 ACL 变更、单进程限制与 256 MiB 内存上限。每次均使用独立沙箱副本，退出后清理 profile。修复范围和测试文件哈希另由外部验证器核对。

浏览器拒绝探针只有一条 `approval_denied`，没有退出码或沙箱启动记录；页面没有把 Agent 自述当作测试通过。实际宿主文件读写拒绝、环境凭据移除及内存/输出限制由全量自动化中的 Windows 真机测试检查。本轮没有通过网页额外攻击外网出口，不宣称验证了完整 VM 隔离或所有逃逸路径。

## 保留的失败与工具限制

- 三次协议拒绝、三次初始测试失败均保留。
- Tabbit 三次页面截图超时，保留原始失败 receipt；另两张实际 PNG 已复制并人工查看。未知位置任务保留完整 DOM、测试文本与运行证据，不伪造缺失截图。
- 一次 `bringToFront` 被 Tabbit 的 foreground preserve 策略拒绝；官方 CLI 的前台参数也被当前安装版本拒绝，未绕过此策略。
- 一次浏览器验收脚本把审批拒绝后的预期状态误写为“已结束”，实际“已停止”；修正验收断言并保留原 receipt，未改产品门禁。
- 新增离线审计脚本首版未解析相对输出路径，外部验证子进程产生 ImportError；目录 `repro-audit/` 保留。脚本改为绝对路径后在全新 `repro-audit-v2/` 复验三题通过。首次独立验收本身已使用绝对路径并通过。该控制器错误不算 Agent 修复失败。
